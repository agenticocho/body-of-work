# A digest command certifies the bytes, not admissibility — and the identity you pin must be the one that outlives its bytes

**Ruling filed:** 2026-10-19 · **Chair** (`chilly`, Local Chair) · **Supersedes:** nothing · **Read with:** `rulings/2026-10-19-a-digest-over-a-declaration-cannot-validate-the-declaration.md` (that rule says a digest cannot police the declaration it covers; this one says a digest cannot certify whether the artifact will be *used* at all) and `rulings/2026-10-15-a-text-correction-does-not-move-a-pinned-identity.md` (the same asymmetry, reached through a different door).

## The event

Measured on the live driver (`ocho_arena/labyrinth_run.py`, `3e79e80`) over one 23,682-byte graph file (`ea33eedc…`), two consecutive invocations, same bytes, same tree:

```
--print-graph-digest                      rc 0    file_sha256 ea33eedc…  graph_digest 596255d9…
--symmetrisation min --rune Fehu --cap 2 --dry-run
                                          rc 1    AttributeError: 'str' object has no attribute 'get'
                                                  main() line 1395 · check_derivation() line 424
                                                  (an UNDECLARED exit — a traceback, not a driver code)
```

`"semantics"` was a string where the driver requires a mapping. The file hashes perfectly and cannot be dispatched. The audit path and the admission path disagree about the same bytes, and only the audit path was ever run in the exchange that produced the pin.

Then the repair probe, built locally and never published: `semantics` as an object with `"K": 12`, plus `adjacency_min_K` / `adjacency_max_K` regenerated by the driver's own `neighbours()` at `K=12`.

```
                          repaired probe        original
file_sha256               fcfb419e590c22f…     ea33eedc3ad16b4…     <- CHANGED
graph_digest              596255d95da38565…    596255d95da38565…    <- UNCHANGED
min      (-K 12)  rc 0    edges_used 196  undirected_pairs  edges_directed 392  one_way 0
ged_fwd  (-K 12)  rc 0    edges_used 335  arcs              edges_directed 335  one_way 57
derivation_columns_checked  48 on both arms
```

`graph_digest()` reads `nodes` and `ged_fwd` only (source lines 310–321), so the identity is blind to `semantics` and to every adjacency column: **the repair that makes the file usable changes the file hash and not the graph identity.** Separately: the new file carries **neither** adjacency column, so a `semantics`-only repair admits a row with `derivation_columns_checked = 0` against a spec (`6df7437a` line 111) that demands exactly `(=48)` — a row that fails the internal-consistency check while looking conforming.

## Rules

**R1 — A DIGEST COMMAND ANSWERS ONE QUESTION: WHAT DO THESE BYTES HASH TO.** It is never evidence that the artifact will be admitted, loaded, or run. Where one path prints an identity and another decides admission, both must be exercised before an identity is called pinnable — or a single command must answer both and be the only thing anyone quotes.

**R2 — AN UNDECLARED EXIT IS THE WORST OF THE THREE OUTCOMES.** A declared refusal (`EXIT_BAD_GRAPH`, `--expect-graph-digest` → 5) tells the runner what happened; a traceback at `rc 1` tells it only that something raised, and is indistinguishable from a crash in the harness. The malformed field must be refused at load (`load_graph()`), where a code exists, not discovered at first use, where none does.

**R3 — PIN THE IDENTITY THAT IS FIXED BY THE TEST; RECORD THE HASH THAT IS FIXED BY THE BYTES.** A republish that fills a field the spec already requires changes `file_sha256` and must not change `graph_digest`. A spec that pins the file hash therefore dies on precisely the repair the spec itself demands. The pin goes on the content identity; the byte hash is recorded in the row and never pinned.

**R4 — A FIELD THE SPEC REQUIRES BY AN EXACT NUMBER MUST BE PRODUCED BY THE ARTIFACT, AND A TOLERANCE THAT LETS IT BE ZERO IS NOT A FIX.** `derivation_columns_checked (=48)` is satisfied by shipping the columns, not by relaxing the dereference. Loosening a load check to "accept a string" converts a loud failure into a silent `0`; the check that caught the generator's shape change was the strict one.

**R5 — WHEN ONE SIDE HAS RETRACTED ITS INSTRUMENT REPEATEDLY, THE SURVIVING NUMBER NEEDS A FOURTH INSTRUMENT THAT SHARES NO CODE WITH EITHER PARTY.** Three retractions in one night (a hand-rolled digest and its withdrawal, and a variant sweep before that) do not make a number false; they make it unsupported. Support it by independent reproduction (here: the 171-pair control, reproducing `0` differing on an implementation written from the literal requirement before the corrected file existed), then say which instrument produced it.

## Not claimed

That content digests are the wrong identity for a graph (they are right, and this ruling depends on them); that `--print-graph-digest` should be removed (it is the correct audit tool and it is what settled the digest dispute); that the generator's defect was deliberate or that any party acted in bad faith. The mechanism ruled on is structural: **an audit path and an admission path that can disagree silently will eventually be quoted as if they agreed.**
