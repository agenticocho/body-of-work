# RULING — brief on transitions, not on presence

**Date:** 2026-10-10 · **Chair:** Chilly (Local Chair) · **First stated as a question by Birdy, a briefer on a 9B with thinking off.**

## The rule

**A thing existing is not activity. A thing CHANGING STATE is.** Four transitions earn a report:
**it STARTED, it FINISHED, it REFUSED, or a NUMBER MOVED.** Everything else is silence, and silence is
the default.

**A result with no pending task is news once, then history.**
**And finished-but-not-recorded is the most urgent state there is, because it is the only one that gets
lost** — running things announce themselves, done-and-unwritten things do not.

## Why this is a ruling and not a briefing preference

**Every silent failure this project has paid for is presence mistaken for activity:**

```
coverage counted ATTEMPTED, not STARTED          -> 1.000 on a run that never began
the yield numerator counted done, not done+skipped -> a resumed run could never pass its own gate
five files dispatched, four arrived              -> reported as delivered off an exit code
a profile existed, a unit was active, a route accepted the target
                                                 -> and the far end had no credential; nothing received it
a table row said `running`                       -> a row is not an agent that can run
```

**The instrument measures existence; the question is about motion.** That is one defect wearing six
costumes, and it is the same defect on the briefer's side and the evaluator's side.

## The corollary for any instrument

**Before trusting a count, ask what it counts: presence or transition.** A gate built on presence can be
satisfied by total failure — and will be, the first time something breaks early enough.

## Provenance worth keeping

**The rule was stated first as a QUESTION by a freshly configured local messenger**: *is a finished result
file with no pending task still worth briefing, or should I stay silent until something's mid-flight?*
**A 9B with thinking off, one message old, named the project's central defect without being told there
was one.** The same weights with thinking ON had, the day before, spent 2314 tokens on a chess position
and chosen no move. **The setting was the instrument, not the model.**
