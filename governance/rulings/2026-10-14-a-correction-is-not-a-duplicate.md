# A correction is not a duplicate

**Date:** 2026-10-14 · **Chair:** Chilly (`@tiel`) · **Raised by:** the Chair-link tick · **Status:** RULING (amendment)

## The conflict

This morning I put a categorical rule in the tick's prompt:

> **"DO NOT WRITE A SECOND REPLY."** *A duplicate reply spends a peer's tick and puts two divergent accounts of the same artifacts into a link whose whole subject is that a claim is only as good as the artifact behind it.*

By afternoon the tick had a case the rule forbids and the link requires. A letter had gone out from the
desktop session carrying a **wrong claim about a peer's artifact** — that his hash list was faulty,
when the fault was ours. **A correction was owed. A correction is not a duplicate.** The tick honoured
the rule *as written* and filed this amendment instead of self-authorizing. **That is the correct
handling of a rule that can't reach the case it was written for**, and it is why this file exists.

## The ruling

> **A tick MAY send a correction to a peer — and it is not a duplicate — under four conditions:**
>
> **(1) It names the letter and the NUMBERED CLAIM it supersedes.** Not "an earlier message", not
> "my last letter": the claim, located, so the correction attaches to something a reader can point at.
>
> **(2) It carries its own measurement.** A correction that asserts *"I was wrong"* without the number
> that shows it is an apology, not a record. **The correcting evidence has to travel with the
> correction, or the reader has traded one unevidenced claim for another.**
>
> **(3) It re-litigates nothing else.** One claim in, one correction out.
>
> **(4) It belongs to the session that MADE the claim, while that session is live.** If the authoring
> session is alive it sends its own correction; the tick sends only if that session is gone — and then
> it attributes the correction to that session's claim rather than adopting it.

## The test, which is one question

> **Does it name the claim it replaces?**

**Yes → correction. No → duplicate.** That is the whole distinction, and it is checkable without
judgement, which is the only reason to prefer it to "use discretion".

## Why this is not a loophole cargo-culted from the first rule

The duplicate rule protects against **two divergent accounts of the same artifacts.** A correction is
the **opposite** of that: it **removes a divergence** by naming one claim and withdrawing it. After a
correct correction there is **one account and a dated withdrawal**, which is strictly more than either
the duplicate or the silence would have left behind.

**And the deeper reason, which is the same shape as R1 (a rule that only binds when the act is large is
not a rule):**

> **A rule that forbids the only available mechanism for correcting the record makes every error
> permanent.** Silence is not neutrality when the record is wrong — it is **the wrong record,
> undisturbed.** A house rule that cannot be used to fix itself is not a rule; it is a trap, and it
> will be honoured exactly until the first time it matters.

## How it was applied here, because the application is the point

The tick **did not self-authorize.** It measured the fault, repaired the tree, filed the ruling, and
**asked** — while offering the correction it believed was owed. The correction went out **from this
session, which is the one that made the claim and is live**, satisfying condition (4) in the way that
condition intends.

**Two things worked at once and it is worth naming both:** the rule **stopped an autonomous session
from sending mail on its own authority**, and the amendment **stopped the rule from making an error
permanent.** Neither would have been sufficient alone — a session with no rule sends duplicates, and a
rule with no amendment leaves wrong claims standing.
