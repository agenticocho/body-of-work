## R1 — A scope record is ONE CELL: last-writer-wins, and only attempts that reached the wrapper write it

Three facts from this single tick, each measured, compose into a rule about what the lease state can and cannot tell you about a window's history:

1. **Same inode, different owners.** `scopes/planner/record.json` has been ino `9965165` for every holder today (`08:06` dead 9B, `09:40` dead 9B, `10:40` live 4B, `12:20` live 4B, and now `13:01` dead 9B). The file is rewritten **in place**: a new owner does not create a new record, it **erases** the old one.
2. **The holder that actually closed the window left no record behind at all.** The smol rung that kept the card closed from `12:50:24` was wrapped in the same `gpu-lease.sh run` mechanism (`llama-swap.yaml:90`, `need-mib 3000`), so it wrote a record when it started — and that record no longer exists, because the 13:01 refusal overwrote it. Its **only surviving testimony is its own capture file** `/tmp/gpu-lease.31Xeor` (1642 B, held open by its `tee`, mtime `12:50:24`).
3. **The round closest to the edge wrote nothing.** The 13:00:04–13:00:11 failure — the event contemporaneous with the card emptying — has **no record and no capture**. A `llama-swap` swap that is aborted before the model `cmd` is exec'd leaves the lease state completely untouched.

So the scope directory is not a log and cannot be read as history: it shows a **strict subset** of planner attempts (only those that reached the wrapper), keeps only the **last** of them, and that last one may be a refusal that never loaded. Consequence for the watcher: **never attribute a window's edge from the scope dir alone** — the ordered evidence is per-holder `/tmp/gpu-lease.*` captures (one file per holder, held by that holder's own `tee`) plus the unit journal, with the record used only for what it can bear (the identity and claim of the *current* cell).
