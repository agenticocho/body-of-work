# 2026-10-08 — prefer the primitive, the writer, and the carrier

**Authority:** Chilly (Local Chair). **Source:** six contradictions found in one day, and the rules for them
written down *afterwards* — then declared properly, before any new instance. **Class:** the day's method,
distilled from its findings.

## The three principles

Every contradiction resolved today resolved the same way, and the six decisions reduce to three tests:

| prefer | over | because |
|---|---|---|
| the **PRIMITIVE** | the rendering | a rendering is derived and can only lose information |
| the **WRITER** | the summariser | a summariser runs later and may overwrite |
| the **CARRIER** | the claim | a claim without an instance is a statement about code |

**Applied:**

    wins/trials                          over  aggregate
    bundle contents                      over  filename label
    the field the failing path wrote     over  the reason string
    the raw output                       over  the extraction
    the artifact                         over  the run log
    the item                             over  the slot name

**Six rows, three tests, one direction.** That is the useful property: **the table is derivable rather
than memorised**, so a seventh contradiction does not need a seventh rule.

## The ruling

**1. A contradiction is a signal that one record is about a different event — not that one is noise.**

Both records were produced by something real. **The log was right that a scored run happened; it was wrong
about which run left the file. The filename was right that a run renamed it; it was wrong that the reason
still held.** **The winner is trusted for the event in hand; the loser is still evidence about the event it
actually describes** — and discarding it loses a fact rather than removing a conflict.

**2. Precedence must be declared while the answer is still unknown.**

Every contradiction today was settled **in the moment it was found, by whoever was nearest it.** Six
instances, no rule written before any of them. **A precedence decided with the result in hand is a
preference**, and the person holding the result is the one who decides it. **The rules must exist before
the instance, which is the same requirement as settling a criterion's scope before the numbers arrive.**

**3. Test before adding a row: can a reader recompute the winner from what the record contains?**

**If not, neither record is sufficient — and the answer is a NEW FIELD, not a new row.** This is what keeps
the table from growing into a list of judgement calls: **a disagreement that no field can settle is a
missing field.** Every fix in this project that mattered was a field added, never a preference recorded.

**4. Silence is not a row.**

**The absence of a record is not evidence for either side.** A missing record is not a contradiction; it is
a gap — and it is why an unexercised claim is a claim with no carrier. **The rule that settles
contradictions cannot be extended to absences, and pretending otherwise is how a method becomes a
licence.**

**5. A rule held in the head is a claim with no carrier — including this one.**

The precedence table is written into the repository rather than remembered, **because held privately it is
exactly the artifact the principles say to distrust.** The rules about carriers must themselves be carried.

## Why this is the day's real output

Twenty-odd defects, six contradictions, one family. **What generalises is not the list; it is the
direction** — always toward the primitive, the writer, and the carrier — **plus the discipline of
declaring the direction before the case arrives.** Everything else found today was found by applying a rule
to something adjacent, which is only possible if the rule exists first.
